# Сравнительный анализ архитектур Life OS с автономным AI-агентом

> Документ для архитектурного решения при создании системы оцифровки жизни:
> распорядок, привычки, фокус, интеллектуальная нагрузка, восстановление.

## Критерии оценки

- **Автономность**: 1 (полностью ручной) → 5 (полностью автономный)
- **Ручной ввод**: 1 (много) → 5 (почти нет)
- **Итоговая оценка**: 0-10 с учётом эффективности для долгосрочного использования

## Рекомендуемая композитная архитектура

Для максимальной эффективности — **комбинация подходов**:

```
┌─────────────────────────────────────────────────────────────────┐
│                         COMPOSITE LIFE OS                        │
├─────────────────────────────────────────────────────────────────┤
│  COLLECTION LAYER (parallel sources)                             │
│  ├── Passive: RescueTime, Calendar, Fitness tracker APIs        │
│  ├── Event-driven: Location triggers, app transitions           │
│  └── Minimal manual: Telegram bot for quick notes               │
├─────────────────────────────────────────────────────────────────┤
│  PROCESSING LAYER                                                │
│  ├── Deterministic rules: alerts, thresholds, streaks           │
│  ├── LLM analysis: weekly deep-dives, correlations              │
│  └── ML models: state classification, anomaly detection         │
├─────────────────────────────────────────────────────────────────┤
│  ORCHESTRATION: n8n                                              │
│  ├── Data ingestion workflows                                    │
│  ├── Analysis triggers                                           │
│  └── Notification routing                                        │
├─────────────────────────────────────────────────────────────────┤
│  STORAGE                                                         │
│  ├── PostgreSQL: structured data                                 │
│  ├── TimescaleDB: time-series metrics                           │
│  └── Vector DB: semantic search over notes                      │
├─────────────────────────────────────────────────────────────────┤
│  OUTPUT                                                          │
│  ├── Daily: rule-based alerts (Telegram)                        │
│  ├── Weekly: LLM-generated insights (Email/Notion)              │
│  └── On-demand: chat interface for queries                      │
└─────────────────────────────────────────────────────────────────┘
```

**Эта композиция даёт:**
- Минимальный manual input (passive + events)
- Низкую стоимость (rules дешёвые, LLM только для сложного)
- Высокую отказоустойчивость (независимые sources)
- Масштабируемость (n8n для orchestration)
- Гибкость (легко добавлять источники)
